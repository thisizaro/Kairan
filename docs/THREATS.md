# Kairan: Threats (STRIDE)

**Reviewed at Gate G0 by security-reviewer; rulings M-D23 to M-D37.** Source: Aro's approved design of 2026-11-05 (not in this repository); the PRD is the top source of truth. Invariants I1-I6 are defined in `docs/PRD.md`. Scenario IDs S1-S13 are the chaos scenarios (ARCHITECTURE §11, M-D50). Every row cites its proof: a test, a PLAN task or a decision. G2 checks that each cited test exists and passes.

Assets: the policy in force on each proxy; the data inside the customer network (payloads, prompts, PII); signing keys; the apply log.
Trust: admins' machines and the proxy's local config are trusted; the control plane and the network are **not**.

| # | Threat | STRIDE | Mitigation | Proof |
|---|---|---|---|---|
| 1 | **Forged policy:** fake control plane, man-in-the-middle or offline bundle file sends a policy | S, T | Proxy accepts only an envelope with 2 valid ed25519 signatures from 2 distinct trusted keys over the exact bytes; tenant, version and expiry checked; trust root only in local config, with a floor of threshold 2 and skew 5m (M-D33); offline import goes through the same `trust.Accept` (P-11) | I1; S5 (unsigned, 1-sig, wrong tenant, corrupted); unit + fuzz in `trust` (T-03, T-04); golden envelopes (M-D34); P-11 repeats the S5 cases |
| 2 | **Compromised control plane:** attacker owns kairan-cp. It can lie in the fleet view, serve each proxy any older or newer signed version it holds (selective serve of a superseded version; there is no revocation), and it sees policy content | S, T, I, D | CP can distribute but not create valid policy; proxies verify independently; CP cannot change keys or threshold; on CP loss proxies stay fail-static. Short expiry bounds how long a superseded version lives. Proxy local metrics (P-09) and kairanctl evidence cross-check the CP timeline against proxy apply logs (T-07); every status carries the apply-log anchor `log_seq`/`log_head` (M-D29, M-D35). Production idea, not built: admin-signed minimum-version notices distributed like policies | I1, I2, I3; S12, S5; M5, M6; T-07 flags version, seq or head mismatch. Policy content visible to the CP and no revocation: LIMITATIONS (O-08; M-D37) |
| 3 | **Rollback replay:** old valid policy re-sent to widen permissions | T, E | Version must be greater than the applied one; rollback is a new higher version | I2; S5 (old version); unit table in `trust` Accept |
| 4 | **Freeze / expiry:** attacker blocks updates so a stale policy lingers | D, E | Expiry (default 72h) triggers safe mode (`read_only` default or `deny_all`, nothing wider; M-D33); expiry judged at `effective_now` (M-D30); fleet page and metrics show it | I3; S7 |
| 5 | **Tampered disk file:** policy or apply log edited by hand, or an older valid policy put back | T, R | Policy re-verified at load: failure means deny-all and a tamper report; stored version below the apply log means Tampered; apply log is hash-chained, tail truncation caught by the CP anchor; writes are temp+fsync+rename, Save then Append (M-D33, M-D35) | I3, I6; S6; unit in `proxy/store`, `proxy/applylog`; break test: older valid envelope plus truncated log (`test/break`, M-D33, M-D35). An attacker with disk write plus config write can replace trusted keys: out of scope, LIMITATIONS (O-08) |
| 6 | **Spoofed proxy status:** someone posts false "applied vN" for a proxy | S, R | Demo: per-proxy enrollment token on status/poll, compared with `crypto/subtle`; token bound to one proxy ID and its enrollment tenant; auth before any body read. Production: mTLS client cert. Strict schema (M-D26, M-D31) | C-04 table: missing or wrong token 401, other proxy's token 403, cross-tenant poll or status 403 (M-D31) |
| 7 | **Payload / PII leak to the control plane** | I | `wire` types carry metadata only; strict decoding rejects unknown fields; CP-side logs and metrics carry no call data; proxy-local logs carry role and tool name only, never arguments, results or prompts; metric labels are `wire.ID` only; user IDs only HMAC'd | I4; S10; M8 (0 canary hits). Status path covered: `TestStatusReportCannotCarryPayload` in internal/wire, including `log_seq`/`log_head` (M-D3, M-D25, mutation-checked) |
| 8 | **Slow-client and huge-body DoS** on the CP or proxy | D | CP: ReadHeader 5s, Read 10s, Write 40s, Idle 60s, 8 KiB headers; `http.MaxBytesReader` with wire limits; one long-poll per proxy ID, global cap 5,000 with 503 `unavailable` + Retry-After. Proxy MCP listener: ReadHeader 5s, Idle 60s, 8 KiB headers, 1 MiB body (413), per-call upstream timeout 60s. Client timeouts: status 10s, poll hold + 10s, kairanctl 30s (M-D9, M-D31) | C-04 and P-02 tests: slow header cut off, oversize body 413, cap 503, second poll replaces the first; Q break-tests the numbers (M-D31); M7 for load |
| 9 | **Stolen API keys** (agent role keys, admin token) | S, E | Demo keys map to one role each so blast radius is that role; constant-time compare; rotate by config; production: OIDC + mTLS | G2 checklist: every key and token compare uses `crypto/subtle`. LIMITATIONS (O-08): demo auth is weak by design; one admin token sees all tenants (M-D24) |
| 10 | **Leaked signing keys** | S, T | Private keys live only on admins' machines; 2-of-N means one leaked key cannot publish; `.gitignore` covers `*.key`, `*.seed`, `*.priv`, `*.pem`, `keys/`, `.env` except `test/fixtures/TEST-ONLY-*`; `kairanctl keygen` writes 0600 and never overwrites; test keys only as `TEST-ONLY-*` in `test/fixtures/`; kairan-proxy warns and sets a metric if a trusted key is a TEST-ONLY key; `make demo` generates fresh keys (M-D37) | I1; G2 repo secret scan. Key revocation and rotation distribution: described for production, not built (LIMITATIONS, O-08) |
| 11 | **Agent exceeds its role** (calls a tool its role may not use) | E | Default deny; byte-exact, case-sensitive matching, no bare `*` (M-D32); `tools/list` hides tools; `tools/call` re-checks; safe mode blocks W/X | I3, I5; unit table in `policy` matcher and `proxy/enforce` |
| 12 | **Proxy clock manipulation** to defeat expiry (e.g. NTP rewind by a network attacker) | T | Expiry uses `effective_now = max(wall, persisted high-water, wall at apply + monotonic elapsed)`; high-water persisted at least every 60s and at shutdown; wall more than 5m behind high-water reports `clock_untrusted` and a metric; skew at most 5m (M-D23, M-D30, M-D33) | P-10 tests with the fake clock (Set moves wall only). LIMITATIONS (O-08): root on the proxy host defeats it; recovery from a bad forward jump is deleting the high-water file |
| 13 | **Request smuggling past enforce:** JSON-RPC parser differentials (duplicate or case-variant keys, batch arrays, SSE responses) let a `tools/call` reach the MCP server unchecked, or a hidden tool appear in `tools/list` | E | Strict enforce spec (M-D33): strict token scan rejects duplicate and non-lowercase keys at envelope and `params` level; batch denied; only `application/json` requests inspected, others rejected; forward exactly the inspected bytes; `tools/list` filter handles JSON and `text/event-stream`, empty list if unparseable; any parse failure that could be `tools/call` is a logged deny | I3, I5; P-02 acceptance tests; `test/break/enforce` |
